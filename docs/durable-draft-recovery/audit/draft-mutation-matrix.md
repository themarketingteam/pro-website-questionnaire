## Reading the matrix

- **Browser** means the `redux-persist` state stored under `persist:pro-questionnaire-root`, or an explicitly named local backup. A local React state change alone is **No**.
- **Draft** means a `ProFormDraft` create/update is queued or synchronously requested for this mutation. **Partial** means the value may arrive only in a later unrelated snapshot, or the snapshot is ordered before coupled cleanup.
- **Event** means a `ProFormDraftEvent` is requested for this mutation. Event creation is best-effort and its failure is swallowed.
- **Submission/PDF** means the resulting committed value is a source for that output, not that the mutation immediately produces the output.
- **Atomic** means all coupled form-state and durability changes occur as one logical mutation. A single React setter is not enough.
- `updateResponse` dispatches `setResponse`, may dirty textarea metadata, schedules a debounced draft snapshot, schedules/creates an event, recalculates validation, sets touched, and increments autosave UI. Those are separate operations.
- “Dormant” means code exists but no current question in `QUESTIONS` renders that path.

## Confirmed mutation bypasses

The following are current, code-confirmed gaps rather than hypothetical failures:

1. Q5 `onAdd`, `onUpdate`, `onRemove`, and `onSetPrimary` dispatch Redux directly and never call `queueDraftSave` or `queueDraftEvent` (M021–M024, M028).
2. `resetQuestion` and Clear All change Redux/browser state but do not save or supersede the server draft and do not emit mutation events (M018–M019).
3. Parent `no` schedules a response snapshot before conditional-child cleanup, so the scheduled snapshot can retain hidden child content (M011, M013).
4. Validation-only, touch, collapse, and textarea validation metadata changes are not represented in a contemporaneous `ProFormDraft` snapshot (M003–M005, M015–M017).
5. Numeric range input, manual location text, Google search text, image working tags/partial people, confirmation credentials, file bytes/progress/errors, and dormant AI working text remain component/browser-object state until an explicit commit (M020, M025, M027, M029–M034, M040, M042, M047, M051, M053–M058).
6. There is no `visibilitychange`, `offline`, or `online` persistence/replay path (M067–M069).
7. The public questionnaire rehydrates browser Redux but does not read a `ProFormDraft` on reload (M065).
8. `beforeunload` backs up Redux slices only; it excludes `textValidationMeta` and all component-local editors (M066, M070).

## Question 5 deep audit

### Current shape

`responses['5']` is an array of plain location objects. A current Google selection has this synthetic shape:

```json
{
  "name": "Example City, XY",
  "label": "Example City, XY",
  "lat": 35.1,
  "lon": -86.7,
  "place_id": "synthetic-place-id",
  "source": "google",
  "originalName": "Example City, XY",
  "originalLabel": "Example City, XY",
  "isGreaterArea": false,
  "isCity": true
}
```

A manual entry uses the same keys, `lat`/`lon: null`, `source: "manual"`, a `manual-<timestamp>` place ID, and `isCity: false`. The primary location is a separate zero-based numeric index at `responses['5_primary']`; missing/falsy values are read as `0`.

| Handler | Redux/browser | Draft | Event | Validation | Reload/close behavior |
|---|---|---|---|---|---|
| `onAdd` (Google or manual) | Direct `setResponse('5', newLocations)`; browser-persisted | No immediate save | No | Recomputes min/max 1–5 | Committed array restores from browser; manual/Google query does not; server recovery misses it until later save |
| `onUpdate` | Direct `setResponse('5', newLocations)` | No | No | Does not recompute | Browser restores update; server may remain older |
| `onRemove` | Direct list update, then direct `5_primary` repair | No | No | Recomputes min/max | Browser restores both if persist completes; server may contain old list/index |
| `onSetPrimary` | Direct `setResponse('5_primary', index)` | No | No | None/bounds not checked | Browser restores index; server may keep old index |

If the removed item is primary, the handler sets primary index to `0`. If an item before the primary is removed, it decrements the index. Because list and index are separate dispatches, this invariant is not atomic. Required future action: `mutateLocations({operation, itemId/index, expectedRevision})`, deriving the list, primary index, validation, browser journal, draft snapshot and event from one post-reducer revision.

## Conditional-child deep audit

| Parent | Children | Visible when | Required while visible |
|---|---|---|---|
| `1` | `1.1`, `1.2` | parent answer `yes` and parent expanded | `1.1` required; `1.2` informational |
| `2` | `2.1`, `2.2` | same | both required |
| `12` | `12.1` | same | required |
| `14` | `14.1` | same | required |
| `23` | `23.1` | same | optional |
| `25` | `25.1` | same | optional |

When a parent becomes `no`, `updateQuestionValidation` sets the parent complete and, per child, clears validation, calls `deleteResponse`, clears touched, and collapses. `deleteResponse(childId)` also deletes `${childId}_other`, `${childId}_primary`, that child’s `textValidationMeta`, validation, touched and expanded entries. The page-level loop then issues some redundant slice resets. Component-local editors disappear by unmount, but no explicit cleanup exists; their loss is therefore incidental to rendering, not a durable mutation.

The critical ordering is parent response -> queued snapshot -> event -> validation/child cleanup. The queued snapshot was built from `{...responses, [parentId]: 'no'}` before cleanup and can retain hidden child responses. Browser rehydration v3 later removes hidden child responses, but that does not repair an already written server draft. Required behavior is a parent reducer mutation followed by a snapshot made from the resulting complete form state, including deletion tombstones or a new revision.

## Current final-submission contract

1. **Source:** `handleConfirmSubmit` passes the page’s current Redux `responses`, validation/touched/expanded maps, credentials/session and the modal’s local business/domain values. `submitProQuestionnaire` shallow-copies the top-level response map as `responseSnapshot`.
2. **Validation timing:** `runFinalValidations` completes before the confirmation modal opens. Text validations run concurrently and update Redux individually. The submit helper then separately repairs and validates the transformed payload.
3. **Draft flush:** opening final submit clears the pending draft-save timer. The helper emits submit stage/attempt events and awaits a best-effort `saveDraftNow(status:'submit_attempted')`; failure does not abort submission.
4. **PDF timing/source:** confirmation PDF uses live Redux `formData` plus local modal credentials. After success, the callback copies business/domain and `responseSnapshot` into `submitted*` local page state before resetting Redux; Thank You PDF uses that memory snapshot.
5. **Fallback:** final entity creation retries and can create a durable intake. A normal fallback later marks the draft submitted. Transform/validation fallback success returns early, so the draft can retain an earlier attempted/failed status even though the UI succeeds.
6. **Redux/browser reset:** success callback calls `resetForm`; redux-persist later writes cleared form slices. It does not explicitly purge/flush storage. `credentials` and `textValidationMeta` are not cleared by `resetForm` (credentials are not whitelisted; text metadata is whitelisted and remains).
7. **Draft status:** normal success awaits `saveDraftNow(status:'submitted', finalSubmissionId)` before the page success callback, but draft errors are swallowed. Events are also best-effort.
8. **Old timers:** the draft-save timer is cleared and guarded by `hasFinalSubmittedRef`; queued per-text event timers are not cleared/guarded at submit success and can emit after success.
9. **PDF regeneration:** submitted answers remain available only in the mounted page’s `submittedFormData`. A reload loses that local snapshot; no receipt lookup is used for PDF regeneration.

## Required mutation test families

Every `T-MUT-*` test must assert the post-action Redux state, persisted browser JSON, draft record revision/payload, event record, final mapper result and PDF model result where applicable. Every `T-ATOM-*` test must deliberately pause between current dispatch/write steps to prove the inconsistent state and later certify the atomic replacement. Offline/close tests must run with fake timers plus a reload from both browser and server sources.
